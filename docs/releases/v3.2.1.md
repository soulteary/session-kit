# session-kit v3.2.1

This patch accepts bounded application-clock differences when revocable Fiber
sessions are read or saved by another replica. It uses the smaller of one second
and 1% of the configured lifetime for the future-deadline plausibility check.
The module remains `github.com/soulteary/session-kit/v3` and requires Go 1.27.3.

Immutable deadlines, expiration rejection, atomic revocation, tombstones and
backend TTL checks are unchanged. The allowance is not an expiration grace
period. Application and Redis clocks must remain synchronized.

## Upgrade and rollback

Upgrade the application dependency and rebuild its binaries:

```sh
go get github.com/soulteary/session-kit/v3@v3.2.1
```

Keep the same dedicated revocable-session namespace, configured lifetime and
Redis dataset. No record migration or reauthentication is required when
upgrading from v3.2.0. Mixed replicas retain the same record format, but v3.2.0
replicas may still reject identifiers issued by a slightly ahead clock. Replace
all replicas to obtain consistent acceptance.

Rollback restores the stricter future-deadline check and can reject otherwise
unexpired sessions issued by an ahead replica. Keep clock synchronization and
the revocable namespace intact; do not delete tombstones or copy records into an
ordinary storage namespace to work around a rejection. Require a fresh login if
a session cannot be accepted. Expired and revoked identifiers remain rejected
in either version.

For an upgrade from an older release, follow the additional namespace and
reauthentication requirements in the [v3.2.0 migration](v3.2.0.md).

The release workflow verifies the tag, module path, tests and security scan.
This library has no service binaries or container images; its published
artifacts are the signed source tag, GitHub Release and Go module.
