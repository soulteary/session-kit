# session-kit v3.2.0

This release adds opt-in revocation-aware sessions. The module remains
`github.com/soulteary/session-kit/v3`, requires Go 1.27.3, and keeps existing
constructors, `Storage`, and ordinary `SessionConfig` behavior compatible.

## New APIs

- `RevocationStorage` provides `GetSession`, `SetSessionIfActive`, and
  `RevokeSession`; memory and Redis storage implement it.
- `NewRevocableSessionID` and `RevocableSessionDeadline` provide random IDs with
  immutable absolute deadlines. `DecodeActiveSession` distinguishes active
  envelopes from tombstones and rejects ordinary stored values.
- `fiberadapter.RevocableSessionConfig` connects this storage contract to Fiber
  sessions. Invalid lifetimes and unsupported backends fail configuration.
- `ErrSessionRevoked`, `ErrSessionExpired`, and `ErrSessionEncoding` distinguish
  rejected writes and malformed records.

## Guarantees and limits

For a given identifier, revocation and writes serialize under one memory lock or
one Redis Lua operation. A stale writer cannot recreate that identifier after
revocation. Tombstones remain until its immutable deadline; writes past that
deadline fail even after the tombstone has expired. Backend TTLs are capped by
that deadline. Redis uses its server clock during atomic operations.

This is an identifier-level guarantee. It does not cancel requests already in
flight, revoke every session for a user, or prevent application code from
minting a different authenticated identifier from stale in-memory identity.
Perform authentication and identifier rotation at deliberate application
boundaries; account-wide revocation needs an additional application policy.

The absolute lifetime comes from the application's configured expiration.
Although `DefaultConfig` uses 24 hours, this release does not mandate a 24-hour
limit for every consumer. Stargate's 24-hour policy is its own configuration.
Existing ordinary sessions retain their previous semantics.

## Migration

1. Choose a new dedicated storage prefix and configure all application instances
   to use it. Reauthenticate old sessions; do not copy ordinary payloads into
   the new namespace or share it with legacy `Storage.Set` writers.
2. Opt in with `fiberadapter.RevocableSessionConfig(manager)` and handle its
   configuration error. Other consumers can implement `RevocationStorage`.
3. Permit Redis `EVAL`, `GET`, `SET`, `DEL`, and `TIME` on the dedicated keyspace.
   Keep application and Redis clocks synchronized. This API does not add context
   cancellation to the legacy storage interface.
4. Do not delete tombstones while stale writers may remain. Bulk `Reset` is
   disabled by the revocable Fiber adapter; rotate the namespace instead.

Install the release with:

```sh
go get github.com/soulteary/session-kit/v3@v3.2.0
```

The release workflow verifies tags and module paths; it does not itself create a
