# session-kit v3.2.2

This patch makes `fiberadapter` work with Fiber v3.7.0, requires Go 1.27.4 and
selects `redis-kit` v1.8.2. The module remains
`github.com/soulteary/session-kit/v3`.

## Fiber v3.7.0

From v3.7.0, Fiber's session middleware stores a session under `session:`
followed by the session ID instead of the bare ID. With session-kit v3.2.1 and
Fiber v3.7.0, revocable sessions fail to save, and ordinary sessions are written
under a key that a `Manager` on the same backend does not use.

`fiberadapter.Storage` and the storage behind `RevocableSessionConfig` now
remove that prefix. The backend stays keyed by the session ID, as it was with
earlier Fiber versions, so existing records remain readable and no record
migration is needed.

`fiberadapter` now requires Fiber v3.7.0. Go's minimum version selection raises
Fiber to v3.7.0 in applications that import `fiberadapter`. Review the Fiber
v3.7.0 release notes for changes outside the session middleware before
upgrading.

One result differs with Fiber v3.7.0. When a request saves a session that
another request in the same process has already destroyed, Fiber drops the save
before it reaches the storage and `Save` returns nil. With earlier Fiber
versions the storage returned `ErrSessionRevoked`. Nothing is stored in either
case, and the session stays revoked. A revocation made by another process is
still reported as `ErrSessionRevoked`. Handlers that treated that error as the
only sign of a concurrent logout should not rely on it for same-process logouts.

## Go 1.27.4

Go 1.27.4 carries security fixes to cgo, the go command, the compiler, the
linker and `net/http`.

## Upgrade and rollback

```sh
go get github.com/soulteary/session-kit/v3@v3.2.2
```

Rebuild with Go 1.27.4 or newer. Keep the same storage namespace, configured
lifetime and Redis dataset. No record migration or reauthentication is required
when upgrading from v3.2.1 with Fiber v3.6.x.

Applications that already ran Fiber v3.7.0 with session-kit v3.2.1 and ordinary
(non-revocable) sessions have records stored under the prefixed key. v3.2.2 does
not read those; affected users need to log in again.

Rolling back to v3.2.1 also requires Fiber v3.6.x; v3.2.1 does not work with
Fiber v3.7.0. Records written by v3.2.2 are readable by v3.2.1 with Fiber v3.6.x.

For an upgrade from a release older than v3.2.0, follow the namespace and
reauthentication requirements in the [v3.2.0 migration](v3.2.0.md).
